# P2/P3 个人手工持仓台账调研（2026-10-29）

本文件只做评估，不修改业务代码，不提供投资建议。范围是手工录入、按已接入行情估值的个人台账；不是券商账户同步、交易下单、税务报表或历史业绩回测。以下是可在现有小程序 + 云函数 + 文档数据库中完成的完整最小方案。

## 1. 当前能力和必须新增的边界

- `cloudfunctions/portfolio/index.js` 的 `portfolios/{OPENID}` 保存自选 `items/rules/annotations/revision`；当前没有数量、成本、交易流水或现金。`remove` 会清除该自选的笔记和提醒，绝不能在此顺带删除持仓。现有自选上限免费 5 / VIP 30 也不能直接用作持仓上限。
- `utils/portfolio-client.js` 只有自选/提醒/笔记 actions；离线缓存明确只读。这种“云端权威、失败不假成功”的模式应复用；持仓缓存另设命名空间和用户隔离，退出/换用户清理。
- `marketData` 已提供验证后的 `assetId/kind/currency/unit/precision`，覆盖 SH/SZ/BJ、HK、US 股票，已验证 ETF/LOF 和两种黄金。港股同一发行人的 HKD/CNY/USD 柜台必须按独立 assetId 计账，不能靠名称合并。美股小数股和黄金小数数量需支持。
- 证券报价已有 `price/prevClose/sourceTime/sessionDate/timezone/marketState/stale/status`；`sessionDate` 取行情源时间的当地日期，`marketState` 取当前取数时刻，两者不等价。行情接口每批 1–30 个；持仓超过 30 个时分批限并发。
- 证券图表使用不复权价格（`fqt=0` 或 raw `day`）。它们可作为经过验证的昨收证据，不能直接充当“历史持仓收益曲线”。缺流水、分红/拆股或价格区间时，无法重建业绩。
- 黄金 `quoteShape` 不输出证券的 `sessionDate/timezone`；`parseSinaQuotes` 明确把 SGE 昨收留作未知。`market-calendar.js` 只覆盖证券 CN/HK/US，SGE/GLOBAL 返回 unknown。不能套用上海自然日、股票日历或抓取时间推断黄金交易日。黄金先完整支持数量/成本/累计盈亏，严格当日盈亏显示“—，交易日/昨收待验证”；若要求黄金当日盈亏也完整可用，黄金 session 适配和证据是发布前置工作。

结论：这不是在自选中加两个成本输入框。流水、现金口径、期初、费用、修改撤销、跨市场交易日、缺价处理、权限和数据迁移属于“持仓”可信成立所必需的新需求。导入导出若被完整版本承诺，也不能只做按钮或仅导出当前列表。

## 2. 产品交互的最小完整闭环

1. 独立“持仓”页，从任意已验证标的搜索添加，无须先加入自选。列表展示标的、数量、摊薄前的移动平均剩余成本、现价及时间、原币市值、浮盈亏、已实现盈亏、最近交易日盈亏；已清仓项目可筛选且当日清仓不能立即从当日统计消失。
2. 新建台账时明确起算时点；选择是否完整记录现金。支持“期初已有持仓”：数量、剩余成本总额、期初日期；不能偷偷把它伪造为该日以市场价买入。记录前历史盈亏未知，不补历史业绩。后续再录入的普通买卖要求不早于起算时点，或通过重设期初/导入完整历史处理。
3. 买入/卖出表单：当地交易日期、同日顺序、数量、成交价、实际成交金额（可选，用于券商舍入）、费用、备注。费用由用户录入，不能按市场猜佣金/税费；默认费用 0 但明确展示。费用最小范围同币种；跨币收费必须显式录为相应币种现金费用，不能相加到原币成本。
4. 流水页支持新增、详情、修改预览、撤销预览、明确保存。修改历史买入会重算其后成本及卖出已实现盈亏；撤销导致后续超卖/现金非法时整次拒绝，并指出冲突流水。输入草稿和取消不写云端；操作失败保留草稿；跨设备冲突要求刷新后重算，不覆盖。
5. 现金页按币种显示期初余额、入金、出金、交易现金流、收入及费用。现金不完整时只显示“已记证券市值”及“证券市值占比”，不能宣称总资产或真实仓位。现金完整时显示原币总资产和仓位；零/负分母显示“—”。若支持负现金必须显式说明，不默认为融资交易；最小方案可拒绝负余额并提示先补充入金。
6. 股票/基金除权导致数量或收入变化时，最小范围支持手工分红/利息、拆股/合股；不自动猜公司行为。否则应显著显示“公司行为未核对，盈亏可能不准确”。停牌、退市或行情缺失不能使持仓消失；保留账本、显示缺价和部分合计。人工估值需单独标记来源和日期，不能冒充实时行情。
7. 导出带 schemaVersion 的 JSON（完整可恢复台账）及适合阅读的 CSV（流水/持仓分表）；导入先校验+预览，显示新增、重复、错误、重算后数量/现金/盈亏差异，明确确认后原子激活。首版支持本产品模板，不承诺解析各券商账单。CSV 防公式注入（文本以 `= + - @` 开头时按文本转义）；JSON 仅允许白名单字段，不信任 owner/汇总/价格。

## 3. 数据模型建议

建议新增独立 `holdingAccounts`、`holdingEntries`、`holdingImports` 三个集合。一个用户先提供一个默认手工台账，模型保留 accountId 以便未来多账户。不要把不断增长的历史数组塞进原有 `portfolios` 单文档。

### holdingAccounts/{serverScopedAccountId}

| 字段 | 含义 |
| --- | --- |
| `ownerOpenid`, `accountId`, `schemaVersion` | 归属由服务端上下文写入，客户端不能指定 owner |
| `name`, `startedAt`, `cashMode` | 起算时点；cashMode=`tracked/untracked` |
| `costMethod` | 固定 `movingWeightedAverage`，不是券商税务/FIFO口径 |
| `revision`, `activeGeneration`, `sequence` | 并发控制、原子导入版本、稳定同日顺序 |
| `positions` | 有界派生缓存：assetId/quantity/remainingCost/realizedPnl/income，币种和单位分明 |
| `cashByCurrency` | 各原币账面现金；未记录不等于 0 |
| `entryCount`, `createdAt`, `updatedAt` | 容量和审计元数据 |

### holdingEntries/{serverDerivedId}

| 字段 | 含义 |
| --- | --- |
| `ownerOpenid`, `accountId`, `generation` | 查询强制用户归属及已激活 generation |
| `logicalEntryId`, `entryVersion`, `supersedes`, `voided` | 修改新增版本，原文保留；撤销保留审计链，不物理删原流水 |
| `requestId`, `payloadHash` | 重复请求幂等；同 ID 不同内容返回冲突 |
| `type` | `openingPosition/buy/sell/openingCash/deposit/withdrawal/income/expense/split` |
| `assetId`, `assetSnapshot` | 标准身份及录入时名称/kind/market/currency/quantityUnit/timezone，元数据服务端验证 |
| `tradeDate`, `tradeTime?`, `sequence`, `timezone`, `tradeSession` | 当地有效交易日+稳定顺序；tradeSession=`regular/manual`，manual 不自动获得严格当日口径 |
| `quantity`, `price`, `grossAmount`, `fee`, `currency` | 十进制定点字符串；买卖数量和价>0、费用>=0；grossAmount 明确来自 quantity*price 或用户实际金额 |
| `remainingCost`（仅期初）, `amount`（现金类）, `splitNumerator/splitDenominator` | 不允许用 0 成本期初替代“不知道成本”；未知成本则浮盈亏不可用 |
| `note`, `createdAt`, `updatedAt` | 用户备注与服务端时间 |

计算使用十进制库或有界整数定点，不累计 JS 浮点误差；金额展示按货币精度，内部成本分摊保留更高精度，清仓时将剩余成本精确归零。`precision` 是行情显示精度，不能直接当数量、成交价或费用精度。黄金数量单位固定为克（AU9999）/金衡盎司（XAU），用户不能把“1克”作为“1盎司”提交；首版避免隐式换算。期初成本不明也应允许记数量，但所有成本相关合计标记不完整。

### 建议 actions（新 holdingLedger 云函数，或 portfolio 显式分域）

| Action | 请求与结果 |
| --- | --- |
| `getAccount` | 返回 account、revision、容量、数据完整性；不顺带返回全部流水 |
| `getValuation` | 持仓派生值、原币分组、行情时间/缺失项、每个标的的估值交易日；不信任前端提交价格 |
| `listEntries` | cursor+limit（如50），按 tradeDate/sequence 稳定分页；revision/generation 防翻页串版本 |
| `previewEntry`, `commitEntry` | requestId、baseRevision、entry；服务端验证/重放/提交，预览不落账 |
| `previewCorrection`, `commitCorrection` | logicalEntryId、expectedEntryVersion、baseRevision、replacement/void；返回后续影响 |
| `previewImport`, `commitImport`, `getImportStatus` | 文件/行校验、幂等去重、staging generation、激活确认；失败保留旧台账 |

错误码至少包含 `revision-conflict/duplicate-request/bad-date/bad-decimal/unknown-cost/oversell/insufficient-cash/unsupported-unit/currency-mismatch/ledger-limit/partial-valuation/import-invalid`。缺行情是估值状态，不应阻止保存真实已发生交易。

## 4. 成本、现金与收益公式（原币逐资产计算）

记持仓数量 Q、剩余成本 C、累计已实现 R，买入数量 b、实际买入金额 B（默认 b×p）、费用 f；卖出数量 s、实际卖出金额 S（默认 s×p）、费用 g。移动平均成本是产品口径，须在页面说明，不能称为券商结算盈亏。

```text
期初：Q=q0，C=用户提供的剩余成本；期初不是损益或入金。
买入：Q'=Q+b，C'=C+B+f，现金'=现金-B-f。
卖出：a=C/Q，转出成本 K=a*s；Q'=Q-s，C'=C-K；
      本笔已实现=S-g-K，R'=R+本笔已实现，现金'=现金+S-g。
清仓：Q'=0 时 C'=0，最后一笔承担分摊尾差。
估值：M=Q*当前有效价格，浮动盈亏 U=M-C。
累计账本盈亏=R+U+已记净收入-独立费用。
浮盈亏率=U/C（C>0 且成本完整），否则不可用。
同币净资产=证券市值合计+该币现金；仓位=证券市值/净资产。
同币单项资产占比=M/该币净资产；现金未知时只给 M/该币证券市值合计。
```

这里的 C 不通过扣减累计已实现收益变成可负的“摊薄成本”；已实现与浮动分别展示。分红 `income` 增现金与收入，不改变剩余成本；若用户希望券商式红利冲减成本属于另一会计模式，不能混用。拆股 r=n/d：Q'=Q*r，C不变，无收益，均价变为原均价/r。合股碎股现金另录收入/处置，不能强行四舍五入数量。

### 当日有交易时的正确金额

对同一资产的估值交易日 D，Q0 是 D 开始前持仓数量（按当日拆股归一），P0 是 D 前一有效交易日原始收盘价（按相同公司行为归一）；Qt 是当前数量，Pt 是 D 内最新已验证常规报价/收盘价。

```text
最近交易日盈亏(D)
  = Qt*Pt - Q0*P0
    + ΣD(卖出金额-卖出费用)
    - ΣD(买入金额+买入费用)
    + ΣD(净收入-独立费用)
```

这等于证券市值变化加交易净现金流，不能用“当前数量×今日涨跌”，也不能用“当日已实现 + 当前持仓×今日涨跌”。分红收入与分红除权下跌配对；没有公司行为数据就标记不可严格比较。入金/出金不是收益。期初转入不是收入，也不是当日买入；期初落在 D 盘中且没有期初市场价时，D 的完整当日盈亏应为“—，起算日不足”，从后续具备基线的交易日开始计算。

跨资产当日汇总应按币种及日期明确分组。北京时间上午的美股最近交易日可能是前一天，A 股是今天；不能无说明拼成“今日收益”。最小完整范围只展示“各标的最近交易日盈亏”和分日期原币小计；若要全账户统一 00:00–24:00 的“今日收益”，需新增统一时区历史估值边界/快照，不能拿各市场昨收简单相加。首版不提供日收益率、年化、胜率或历史资产曲线。

## 5. 交易日、休市、行情缺失

- 只按 asset.timezone 归属日期，美股使用 `America/New_York`（自动夏令时），不能固定 UTC−5，也不能按微信设备日期。买卖 tradeDate 用该市场当地日期，录入时间和服务器创建时间分开保存。相同日期按显式 sequence 重放；不能依赖随机 ID 排序。
- P0 是 D 的上一交易日收盘：周一用上周五，长假后用休市前最后一交易日，半日市用该日实际收盘；“昨天”不是该字段语义。证券 provider 的 prevClose 还须有 `prevCloseDate/basis` 证据或经 raw 日线相邻交易日验证；不能默认周末抓取仍可与“今天”配对。
- 周末显示“最近交易日盈亏（周五日期）”，不重写成周六今日收益；若 UI 一定提供当地自然日“今日”，休市日无真实事件则为0，并另外显示最近交易日数值，二者不能混名。开盘前同理：保留行情真实 sessionDate，不把昨天的收盘价当今天最新成交。
- 首版严格当日计算仅覆盖已验证常规场次。手工记录盘前盘后/其他 manual 场次时，现有常规行情不保证已覆盖该成交，显示“估值价格早于部分流水/口径不足”，当日数值暂停；不得把成交强行挪到常规场次。若要求美股延长时段估值，属于新增数据能力。
- 报价早于最近录入的成交不能当作成交后实时估值而不提示；只记日期没有时间的同日流水亦不能证明覆盖。可显示“按最新可用价估算”及双方时间，对严格日收益保守降级。历史补录则重放成本，但不能制造补录当时的收益点。
- stale/cached/delayed/sourceTime 原样呈现。缺现价的持仓，数量/成本/已实现仍可用；市值/浮动/相关总额显示部分，附“已估值N/M项”，不能把缺价作0或无提示沿用成本。缺昨收只使当日指标不可用，不妨碍当前市值/浮盈。
- 本地日历只覆盖有证据的年份；未知年份或黄金 unknown 不按工作日推断。需要加 `valuationSessionDate/previousSessionDate/basis/complete/reasons` 等估值结果字段，不仅返回一个数字。

## 6. 币种与历史收益的承诺

CNY、HKD、USD 独立展示；港股人民币柜台仍是 CNY，不按 HK 市场强制 HKD。禁止直接展示三币合计总资产、总盈亏和统一仓位。若未来新增人民币折算，必须明确汇率对、方向、来源、时间及是否仅作展示；现金换汇录双腿金额及手续费，不可假定历史汇率等于现汇率，汇兑盈亏另立口径。

完整备份流水与历史行情也不自动等于可靠历史收益：需要每一时段持仓、现金流、公司行为及定价证据。首版可给“自起算日累计账本盈亏”（成本已知时），不画起算前业绩；期初成本已含历史盈亏时，这个累计数是持仓成本口径，不称为起算以来投资回报率。历史曲线/区间收益/TWR/IRR 另立范围和验收。

## 7. 事务、容量、权限和迁移

新功能可沿用现有 `db.runTransaction` 模式：远程 metadata/行情和重放在事务外完成；事务内按明确 doc ID 读取归属、baseRevision、幂等记录，全部读完后写入流水版本及 account 派生状态，保证原子成功/失败。追加、修正、撤销都必须修改同一 account revision，使事务外读到的全部流水能由最后的 revision 比较证明仍有效。分页重放读完后再次校验 revision，冲突则丢弃候选，有限重试。不能在事务里调用行情，也不能声称 `where` 扫描全历史已被事务锁定。

当前 CloudBase 文档列出事务最多100操作、30秒、事务中只支持doc不支持where；项目实际是 `wx-server-sdk ~2.6.3`，须在实际环境验证 SDK 和运行时行为后发布，不能把新版 node-sdk 文档当成本项目云端已验证。参考：[CloudBase事务](https://docs.cloudbase.net/database/transaction)。

历史编辑使用“原事件+新版/撤销事件”的审计链，重放只取有效版本，现金/数量任何时点都不能因后续事件补回而掩盖先前超卖。幂等 requestId 必须与流水同事务保存；网络超时后重试同 requestId 返回同一业务结果。台账汇总无需每次行情刷新写数据库，行情只用于读时估值。

建议首版产品上限：每用户1台账、最多100个不同资产、5000条含审计版本的流水、单次导入500行；这是可测的产品限制，不是平台硬限制。派生缓存有界，流水游标分页，禁止每次打开页面下发全部流水。100个资产行情分4批，优先可见项，标记剩余加载状态。后台重放5000条的耗时、内存、读写额度必须实测；若超云函数预算，降低首版上限或做作业，不让半成品状态对外可见。

大批导入不能用一个超过事务操作数的事务硬塞：分批写入隔离 staging generation，验证完整数量/哈希/重放和归属后，用短事务核对旧 revision 并切换 activeGeneration，失败旧账本仍完整可读；重复 commit 幂等。导入期间其他写入导致 revision 改变，提交冲突后重新预览，不悄悄覆盖。废弃 staging 做带归属和超时的后台清理，不能误删活动版本。原有自选数据无须迁移或重置。

容量不能靠“文档上限还没到”保证：官方 FAQ 也不建议无限增长文档数组，参考[CloudBase文档大小说明](https://docs.cloudbase.net/lowcode/faq)。环境配额、读写吞吐、对象存储和计费以实际控制台套餐为准；官方 FAQ 说明容量耗尽会拒绝写入，参考[数据库容量与集合说明](https://cloud.tencent.com/document/faq/876/18436)。这些不是已经核对本用户环境的结论。

新集合全部加入 `initDb` 和 `docs/database-permissions.json`，客户端 read/write=false，仅云函数访问；所有 reads/exports/imports/corrections 强制 `getWXContext().OPENID` 归属，不能只验证格式合法的 accountId/entryId。云函数使用管理权限，数据库禁止客户端不等于函数自动隔离用户。对象存储导入/导出文件同样验证 owner/短期可访问 URL、TTL和内容大小，日志不打印完整个人台账。新 API 用独立 payload 白名单和数值上限，拒绝 NaN/Infinity/科学计数超界/负数量/伪造汇总/错误币种。

## 8. 发布验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 单位/小数 | ETF3位报价、小数股、0.125克/盎司正确；相同金价单位不能误换 |
| 买卖算术 | 第4节8个数值样例全部通过，金额/数量尾差清仓归零 |
| 期初未知历史 | 只知道数量与成本的期初不产生伪造买单/历史收益；盘中起算首日当日不可用 |
| 修改与撤销 | 改早期买单重算后续；撤销导致超卖时整次失败，原账不变；原文可审计 |
| 请求与并发 | 双击/超时重试同 requestId只记一次；双设备同revision一成一冲突；导出/分页串版本拒绝 |
| 自选独立 | 未关注资产可持仓；移除自选/到期会员/删除笔记不会损失账本；重新加入仍可关联 |
| 休市与时区 | 周一/长假后用上交易日收盘；美国DST前后交易日不偏移；北京时间跨午夜分组正确 |
| 当日已清仓 | 当日统计含该笔卖出；持仓默认页可隐藏，但当日汇总不丢 |
| 多币 | HKD/CNY柜台分开，CNY/HKD/USD不直接求总和，不用今日FX重写历史成本 |
| 缺价与回退 | 市场失败仍可记账；缺现价给部分合计，缺昨收只禁当日；黄金未知session显示原因 |
| 公司行为 | 拆股不制造损益；分红价格下跌与实际净收入配对；未知行为明确不完整 |
| 导入导出 | JSON导出再导入数字/顺序/审计一致；重复行、超量、非法币种、CSV公式注入处理；中途失败旧账可用 |
| 权限与额度 | 用户A读改导出B全部失败；无OPENID拒绝；容量耗尽/事务冲突失败不产生半笔账 |

发布前需新增纯计算测试、云函数归属/事务/幂等测试、真实数据库事务烟测和小程序录入→修改→撤销→导出→导入全流程验证。现有自选、笔记、提醒规则回归必须通过；本调研没有执行新功能测试，也不表示云端已部署。

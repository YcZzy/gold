# 多标的行情与提醒设计方案

状态：2026-10-27 已确认采用多接口兜底、自选列表首页、独立标的详情及详情内的提醒设置。首版市场范围和具体会员额度仍按建议值设计。本文不改变现有小程序业务代码。

## 1. 产品范围与推荐方案

首版范围按「保留沪金、伦敦金 + 沪深 A 股」设计。北交所、港股、美股在行情、交易日历和消息适用范围完成验证后接入。所有标的采用统一结构，避免后续增加市场时重写界面。

核心路径：自选列表 → 独立标的详情 → 对应标的提醒设置；新增路径为搜索联想 → 查看详情或原地加入自选。

已确认采用「自选列表首页 + 独立详情」。首页负责比较多个标的的价格与涨跌；详情承接现有金价页面的价格、图表和详细数据。每个详情页绑定固定的标的 ID，提醒设置同样绑定该 ID。用户返回列表后再选择另一只，保留列表滚动位置和排序。

接口请求细节：

- 搜索：`input=<关键词>&type=14&count=8`。结果会混入板块、指数等类别；服务端只保留首版支持的股票类别。直接使用服务端结果里的市场信息和报价标识，禁止单凭六位数字猜市场。
- 单股：`secid=<返回的QuoteID>&fields=f57,f58,f59,f43,f44,f45,f46,f47,f48,f60,f170,f169,f124`。价格缩放按字段精度处理，不能把黄金的固定除以 100 套给所有标的。
- 日 K：明确日期范围、周期和复权参数。到价规则始终使用实际报价；历史图表明确标注复权口径。不同来源的复权口径不能直接拼接。
- 腾讯原始报价需要处理字符编码和字段格式，与东财统一转换为内部行情模型。
- 完整拼音属于后续增强：定期同步股票目录，再在自有目录建立名称、代码、首字母及全拼索引；不能把当前 suggest 接口实测未匹配的全拼能力写进首版承诺。

### 多接口与降级策略（已确认）

按能力配置数据源，各能力独立判定健康状态，不因某一类故障导致所有内容不可用：

| 能力 | 主路径 | 兜底路径 | 最后降级 |
| --- | --- | --- | --- |
| 名称/代码联想 | 东方财富 suggest | 定期同步的本地股票目录索引 | 已缓存搜索结果；无可用目录时明确提示暂时不可搜索 |
| 沪深股票最新报价/批量报价 | 腾讯行情 | 东方财富报价 | 最近有效缓存，标注原行情时间及延迟 |
| 分时 | 东方财富分时 | 腾讯分时 | 同标的缓存图表，提示延迟；没有缓存则重试入口 |
| 历史 K 线 | 东方财富历史 | 腾讯历史，验证相同周期与复权口径 | 相同口径缓存图表 |
| 现有黄金报价与图表 | 保留已验证的黄金链路 | 仅使用明确支持该品种的备用接口 | 缓存与来源状态提示 |

执行规则：

- 搜索和报价请求单源初始超时 3 秒，最多切换一次远端备用源，随后使用缓存或明确失败。总预算初始 7 秒；不堆叠长时间重试。
- 超时、非正常状态、空数据、标的不匹配、无效价格、来源时间不合格均参与降级判断，HTTP 成功不等于行情可用于提醒。
- 连续失败的数据源进入短暂冷却，低频探测恢复后再启用；避免每个用户请求都等待故障源。
- 统一输出标的、价格、币种、来源、行情时间、获取时间、数据状态。前台展示简短「报价延迟」和时间，技术故障详情留在日志。
- 过期缓存可作为带提示的展示数据；触发新提醒必须有通过时效校验的有效行情。来源时间为空时不以获取时间替代。
- 图表按完整请求切换供应商，复权口径、交易时区或单位不一致时不拼接。短时波动基准在切换来源后重新检查连续性。
- 主备能力按市场验证。本次只验证了少量沪深股票，不能由此推断其他市场、所有品种都已覆盖。

## 3. 页面结构与信息层级

底部三个入口：自选、提醒、我的。「提醒」用于跨标的汇总，所有编辑均定位到对应标的；「我的」放主题、通用免打扰、会员权益等全局设置。

### 自选列表首页

1. 顶部：我的自选、已用/总名额、添加按钮。点击添加进入搜索页。
2. 简单列头：名称 / 最新价 / 涨跌幅。名称下用次级文字显示代码和市场，黄金显示品种和价格单位。
3. 列表行：左侧名称与代码，中间价格，右侧带正负号的涨跌幅；名称旁小铃铛仅表示已启用提醒。整行点击进入详情。
4. 管理入口：拖动排序、置顶、移除放在管理模式，普通列表保持干净。首版默认用户自定义顺序，可选按涨跌幅排序。
5. 数据状态：停牌、休市、报价延迟显示为小状态文字；接口失败不把价格变成零。

首版首页不放走势图和大价格卡片，保持每行紧凑且有清晰点击区域。自选较多后可增加「全部 / 黄金 / 股票」筛选；数量少时不展示无必要筛选。保留纸感、黑金主题，涨跌颜色与数值符号共同表达状态。

列表原型：

```
我的自选 3/5                         ＋ 添加
名称                    最新价       涨跌幅
贵州茅台  铃铛              …           …
600519 · 沪市
平安银行                    …           …
000001 · 深市
沪金  铃铛                  …           …
Au99.99 · 元/克
```

### 独立标的详情

点击列表行进入 `详情(assetId)`，页面展示固定的标的名称、代码、市场、单位。首版通过返回自选列表切换标的，避免详情再引入一套股票切换操作。返回保留原列表位置与排序。

1. 顶部身份区：返回、名称、代码/市场、关注状态。
2. 价格主区：最新价最大字号，涨跌额/涨跌幅次一级；附近显示交易状态、行情时间和来源状态。
3. 图表区：分时 / 日 K / 周 K / 月 K。优先复用现有图表，在接入验证后开放对应周期。
4. 简要数据：今开、最高、最低、昨收、成交量、成交额；黄金保留适用数据和国际参考。六项用两行三列，缺失项显示 `--`。
5. 本标的提醒区：`提醒 · 2 条开启`，显示最多两条简短条件，提供「设置提醒」按钮。没有提醒时仅显示「为这只股票设置提醒」。

详情页不放财报、新闻、评论和大量技术指标，信息密度保持接近当前金价页面。搜索结果中的未关注股票可先看详情；设置活跃提醒前需要加入自选，防止绕开自选额度并使管理对象一致。

详情先显示对应标的的有效缓存；没有缓存则用占位状态。名称、价格、走势图必须来自同一标的。快速返回再打开另一只时，旧请求返回结果不得覆盖新页面。按标的保留所选图表周期。

取消关注会同时暂停该标的的提醒并保留配置，在动作确认中明确说明；重新关注后由用户主动恢复。

## 4. 搜索、联想和关注

搜索页顶部输入框：`搜索股票名称 / 代码 / 拼音首字母`。

- 未输入：显示最近搜索，默认不加入推荐股票或行情榜单。
- 输入一个汉字或代码字符后即可联想，输入结束约 300ms 请求；服务端返回最多 8 个候选。输入法组字结束后再提交，旧关键词响应自动丢弃。
- 中文完整名称、名称片段、代码精确匹配优先；其次首字母匹配。同名结果必须显示代码和市场。
- 单条结果：`贵州茅台` + `600519 · 沪市 A 股`；右侧 `+ 自选` 或 `已关注`。
- 点击结果主体进入行情详情，点击 `+ 自选` 原地添加并保留搜索结果，方便连续添加多只。
- 确认具体候选后才展示该股票内容。输入「中」等模糊关键词不自动选择第一只股票。
- 搜索失败保留关键词并提供重试；无结果提示改用股票代码；不以空结果掩盖接口故障。
- 重复添加返回「已在自选」，不消耗第二个名额。搜索和查看详情不受自选数量额度限制。

典型流程：输入「茅」→ 选择「贵州茅台 600519」→ 看现价/图表 → 点击加入自选 → 点击设置提醒。

## 5. 股票提醒交互

### 从独立标的详情设置

详情页的提醒区只展示该标的的规则。点击「设置提醒」，进入 `标的提醒(assetId)`；顶部固定展示名称、代码、价格单位和当前参考价格。新增、编辑、暂停和删除均限定在这个标的内。

首先展示已设置的规则摘要；点击「新增提醒」选择一种类型，再只展示该类型的参数：

| 类型 | 用户需要输入 | 默认行为 |
| --- | --- | --- |
| 涨到指定价格 | 目标价 | 到达或越过后通知一次，成功后关闭 |
| 跌到指定价格 | 目标价 | 到达或越过后通知一次，成功后关闭 |
| 日内涨跌幅 | 相对昨收的绝对涨跌幅阈值 | 每标的每日最多一条该类提醒 |
| 短时急涨急跌 | 15 分钟涨跌幅阈值 | 仅有效报价和有效基准满足时触发 |
| 定时行情播报 | 时间、每天/交易日 | 展示本标的价格和涨跌幅 |
| 收盘简报 | 开关 | 按该市场实际交易日和收盘策略生成 |

规则编辑使用明确「保存提醒」按钮，保存成功后回到摘要列表。金额旁固定显示币种/单位，输入过程只保存草稿，不实时启用中间数字。可暂停、编辑、删除单条规则；价格或条件发生改变后轮换规则版本，使旧任务失效。

首版每标的同一类型只保留一条规则。用户第二次添加同一类型时进入已有规则编辑，避免重复推送和复杂管理。

### 全部提醒页

底部「提醒」入口只承担跨标的汇总，按标的分组。点击规则或「管理此股票提醒」进入同一套 `标的提醒(assetId)` 页面，避免出现两个独立的设置版本：

```
贵州茅台 600519                  2 条开启
跌到目标价 ¥…               一次性 · 开启
日内涨跌 ≥ 2%              每日一次 · 开启

沪金 Au99.99                    1 条开启
工作日收盘简报                    开启
```

顶部只留一条紧凑授权状态：简报次数、预警次数、增加次数按钮。免打扰、最近发送记录放在二级入口，避免首页被通用设置占满。

从微信消息进入时，直接定位到消息对应标的，并可查看触发记录；不能一律跳回沪金页。股票名称必须出现在消息内，价格保留正确币种、单位和来源时间。继续优先复用现有两个模板，股票场景的模板适用性需要在接入时确认。

## 6. 数据与服务端结构

| 集合/模型 | 责任 |
| --- | --- |
| instruments | 统一标的目录：内部 ID、代码、名称、市场、类别、币种、单位、交易时区、各供应商映射、可用能力 |
| watchlist | 用户关注关系、排序、置顶；用户+标的唯一 |
| alertRules | 用户、标的 ID、规则类型、条件、版本、状态；用户+标的+类型唯一 |
| quoteCache | 每个标的的标准化最新行情、来源时间、获取时间、数据源、状态 |
| quoteSnapshots | 按标的保存有界短时历史，用于 15 分钟比较 |
| sendTasks | 关联标的 ID、规则 ID/版本、触发值、时间、模板、发送状态 |
| subscriptions | 继续按用户+模板管理微信订阅授权次数 |
| entitlements | 用户自选和活跃提醒数量上限、会员到期时间，服务端校验 |

接口层建议提供 `searchInstruments`、`getQuote`、`getChart`、`getWatchlist`、`addWatchlist`、`saveAlertRule`。客户端传标的 ID，由服务端映射允许访问的供应商资源，不接受任意 URL。

行情模型同时保存 `sourceTime` 和 `fetchedAt`。缺少来源时间时显示「更新时间待确认」，不能把请求时间当成行情发生时间。预警依赖有效、新鲜、口径一致的报价。停牌、休市、零成交、除权除息和复权变化要分别处理，缺失数据不显示为零。

显示价格保留供应商精度；目标价比较采用标准化数值并保持同币种、同价格口径。短时预警不拼接不同时区、不兼容价格口径的样本，切换数据源后重新验证基准。

## 7. 请求成本与提醒稳定性

- 搜索结果缓存短期复用；股票目录定期刷新，用于名称查询降级。
- 自选列表使用批量行情，按供应商能力分批。多人关注同一股票时共享行情缓存，后台按去重后的标的扫描，不为每个用户重复拉行情。
- 前台只轮询当前标的与当前可见自选数据；页面隐藏后停止轮询。初始可采用交易时段约 15–30 秒、非交易时段降频的策略，再依据实际限流和成本调整。
- 预警后台维持约 5 分钟扫描起步，界面明确说明延迟；不能因会员而承诺数据源尚未验证的秒级预警。
- 重试、超时、来源切换及不明发送结果处理沿用当前安全发送原则。幂等键包含规则 ID 和版本；成功发送后再消费一次性规则。
- 增加标的后，推送预算按用户全局、标的、类型三层控制；到价规则保留预算，常规播报不能独占所有业务名额。微信模板授权余量仍会限制实际发送。
- 交易日历按市场维护；不能把「周一至周五」等同于所有市场的实际交易日。

## 8. 会员预留

建议产品确认后配置免费 5 个自选、会员 30 个自选；金额和最终额度尚未确定。黄金和股票统一按标的计数，两个黄金品种为两个标的。显示数量和关注名额分开：浏览公开搜索结果和股票详情不消耗自选名额。

首次发布多标的时只预留权益结构和服务端校验，不强行接入支付。达到上限时在添加动作上提示 `自选已达 5 个`，提供管理已有自选和查看会员权益；正常看行情时不弹会员窗口。

提醒规则容量独立配置。历史用户已存在的配置保留，不因引入新配额直接删除。会员到期保留配置，允许用户选择保留的免费名额，超额部分暂停；支付和恢复规则在会员功能立项时明确。会员权益不能直接替代现有微信订阅授权。

## 9. 实施拆分与验收

1. 数据验证：搜索、单股/批量行情、分时、K 线统一字段与来源状态；对不同股票进行抽样，不把本次两只股票的成功当作全市场覆盖证明。
2. 浏览与自选：自选列表首页、搜索页、独立标的详情、关注与排序、返回状态恢复、缓存与错误状态。
3. 按标的提醒：规则模型、编辑交互、后台按标的扫描、消息深链、当前黄金配置迁移。
4. 权益预留：数量显示、服务端限额、超限管理；购买流程单独实施。

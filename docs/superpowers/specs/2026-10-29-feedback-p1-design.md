# 评论需求 P1 实施设计

用户已确认按前一轮需求分析的优先级开始实现。本轮只实施功能需求，保留工作区内已有多市场、主题和提醒改动。

## 范围与取舍

采用原有小程序架构增量实现，而不是引入证券终端或完整资产记账模块。依次完成场内基金覆盖、自选备注、图表提醒线、自定义均线及 MACD、列表信息补充。ETF 已在当前工作区接入，LOF 需独立分类与数据身份验证，不能将所有基金误认成 ETF。暂不接入场外净值、持仓、自动交易、AI 建议及 P2/P3 功能。

## 场内基金

复用现有证券报价、分时、日 K、搜索、提醒与交易日历路径。LOF 使用 kind=lof、人民币/份、三位小数的最小精度；只接受在当前市场明确验证的代码与基金类型。搜索、服务端 metadata、缓存恢复、提醒消费的允许范围应一致。无法验证的品种应明确不支持，不伪装成已接入。

## 自选备注

每只已关注标的允许保存 120 字备注与最多 3 个、每个 8 字的标签。详情页编辑，首页展示简短备注和标签。输入只修改草稿，明确点击保存后经 portfolio 云函数事务落库；取消保留上次版本。新增 annotations 映射，旧用户缺省为空；删除自选同时删除其备注，不修改证券主数据。离线写入不假成功。沿用 revision 防止陈旧备注覆盖，不影响已有规则版本。

## 图表与提醒

仅展示本标的已开启的 priceAbove / priceBelow 规则。区间内画虚线及方向标签，区间外不拉伸坐标；图表下方始终列出目标价、相对当前价的有符号距离百分比和是否超出图表范围。列表和规则变更后自动更新，暂停/删除不继续画线。目标价与差额使用标的精度。提醒文字描述的是条件，不是投资建议。

## 技术指标

使用原 Canvas，增加独立纯计算模块。支持最多 3 条、不重复、1–250 日整数均线，可整组关闭；默认 5、10。副图在成交量与 MACD(12,26,9) 间切换，默认成交量；MACD 使用 EMA 首个收盘价初始化，柱值=2*(DIF-DEA)，不足 26 根提示样本较少。设置按设备保存，各标的共用；无效输入不覆盖旧设置。K 线与分时共用提醒线，分时不套用日均线和日 MACD。图例对应实际参数；图表配置不触发新的行情请求。

## 首页信息

在现有价格、涨跌幅之外增加涨跌额和来源行情时间。时间缺失保留待确认，缓存仍标明缓存，不使用本机刷新时间替代。保持窄屏三列布局，备注与时间采用次级信息，不新增桌面式横向表格。

## 验收

Node 测试验证 LOF 分类与数据身份、备注边界及并发隔离、旧数据兼容、指标数值、提醒过滤和距离、Canvas 图层及交互、草稿保存取消、列表信息。运行全量本地回归与 git diff --check。真实云端部署和微信送达不属于本地测试成功的含义；交付明确需要更新的云函数。UI 使用现有纸感/黑金变量与原生表单，控件提供可访问名称，不引入新动画。

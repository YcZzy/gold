# 持仓流程简化

用户认为前两轮仍然复杂，要求梳理所有持仓相关逻辑、简洁设计与紧凑舒适布局。已查看微信模拟器真实黑金空仓页面：空值概览、初始化提示、搜索排序和重复操作占据一屏。

## 最终方向

- 首页保留概览、持仓列表和单一记账入口，币种为小型选择器。交易记录、现金管理、资产明细、备份与说明归入原生「更多」菜单。
- 空仓不展示搜索、排序和清仓开关，空状态直接登记已有持仓；不把未记录现金当作零现金。无现金记录时概览标题为持仓市值，避免总资产空值与强制初始化提示。
- 持仓以名称/市值/盈亏三列紧凑行排列，点击行展开详情与买卖按钮，同一时间只展开一项。数量、均价、来源、备注仅在详情。
- 「记一笔」直接打开表单：当前币种无标的时默认已有持仓，否则默认买入。交易页只展示买入/卖出/已有持仓；现金页只展示入金/出金/可用的期初现金。分红、费用、拆合股归入上下文菜单。
- 交易表单默认仅保留标的、数量、单价和费用；日期、实际成交金额、备注进入更多选项。金额核对只显示必要现金影响，保留手工金额优先及修改数量清空金额的原规则。
- 已选标的收起搜索，支持更换；持仓和自选共同提供候选。卖出可快捷填全部数量，禁止用现价自动充当成交价。历史卖出仍由服务端按当时持仓校验。
- 返回保留本页草稿；记一笔直接继续草稿，不加恢复选择页。其他上下文动作覆盖草稿需确认。离开页面不持久化私密金额。
- 保留显式保存、冲突、幂等重试及导入预览；不改变成本计算、现金约束或云端协议。

验证：测试核心路径与边界，完整 Node 测试，原生模板样式编译，并在开发工具实际查看空仓、表单、现金、历史及返回流程。真实台账不写入测试记录。

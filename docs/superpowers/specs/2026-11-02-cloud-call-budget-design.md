# 月度云调用预算设计

用户已选择：保留分钟级提醒，采用公共快照和操作额度。按100用户、每人5个股票、31天最坏自然月设计。

现有证据：sendTask每轮500股票需17次嵌套行情调用；详情页每分钟报价、图表各一次，额外面板还会查询；read-cache只有失败回退，read-pool只有重叠合并。线上3000次尚无分函数日志，不能准确归因。现有555项测试通过。

采用：每轮扫描只调用一次批量行情函数，函数内部每30个一批、有界并发，最多500个去重股票；保留原每分钟扫描。为全部自选的交易中股票维护公共报价投影，不以提醒授权余额决定前台行情是否更新；规则筛选仍决定任务生成。非交易时段优先沿用最近快照。公共集合只包含asset/quote/updatedAt，不包含用户、规则、持仓、授权、provider请求日志。私有集合权限保持关闭。

前台先读取公共报价快照；有效时不调用函数。缺少或交易中超过2分钟才受额度控制回源，过期/离线回退保留真实来源时间并标记。图表15分钟、搜索5分钟、证券资料24小时、发现5分钟共享本设备成功结果；失败不伪装成功，不改变私密写入语义。

在app初始化安装统一云调用入口，所有前台路径共用每用户月度800单位额度，按北京时间月切换。callBudget以真实OPENID在cloudCallBudgets事务分配100单位（99业务、1领取），多设备和清缓存不会重置账户额度。先预扣最大嵌套次数，再按服务端响应实际调用计数退差额；失败不退，防止超时已计费。portfolio最多61单位，ledger最多32单位，其余1单位。超额在客户端请求发出前阻止并给出提示，保留原有草稿。只读可回退快照；写入不缓存。

31天模型：44640 timer + 44640批量行情 + 100*800客户端调用单位 =169280，余30720用于部署、旧黄金路径及异常。超过500标的明确报容量错误，不静默丢标的。数据库读取及网络请求有独立成本，本预算只针对函数调用。

边界：服务端分配防止多设备/清缓存重复领取；绕过前台直接调用、失败的领取和旧版本仍会额外计费，函数内部拒绝请求仍会产生调用。没有云端统计权限，不能声称绝对计费硬上限或已部署生效。上线需核对只有一个dispatchTimer、无scanTimer，检查按函数用量和实际部署版本，并设置云平台预算告警/可用的额度策略。

备选：延长到5分钟牺牲提醒时效；仅加TTL依赖用户使用时长无法满足规模目标。用户已选共享快照方案。

Timer事件竞争单个分钟扫描锁，避免旧/重复定时触发器再次调用行情；重复触发器自身仍须删除。详细上线步骤见docs/cloud-call-budget-2026-11-02.md。

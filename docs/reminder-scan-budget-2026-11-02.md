# 提醒扫描调用预算优化（2026-11-02）

> 此文记录前次局部优化；后续整体预算、公共快照与新增部署要求以 [云调用预算方案](cloud-call-budget-2026-11-02.md) 为准。
## 范围

针对每月 20 万次云函数调用、100 位用户各关注 5 个标的的场景，减少提醒后台的无效行情调用。保留每分钟一次 `dispatchTimer`，不通过拉长扫描间隔降低提醒时效；前端行情刷新及其他云函数调用不在此次修改范围内。

## 行为

- 每轮分页读取正余额授权，旧黄金扫描与多标的扫描共用该快照。零授权不关闭规则、不创建新任务，充值授权后后续扫描恢复。发送前仍使用事务检查并预占实际模板余额，不依赖扫描快照保证并发安全。
- 价格、日内波动、短时急变只在证券常规交易时段查行情，复用现有日历和美股夏令时判断。午休、周末、已知休市日及未覆盖年份不查询这类证券行情。黄金保持原有有效报价策略，不套用股票时段。
- 定时播报只在应播时间后原有 6 分钟窗口查询，保留跨午夜和应播日期的星期判断。收盘播报只在原有收盘后 10–55 分钟窗口查询；沪金保持 15:40–16:25，伦敦金不提供收盘播报。定时播报不因证券休市而被错误过滤。
- 可用时读取 `instruments` 的已验证元数据；缺少元数据仅依据已有标的 ID 判断市场，不猜币种或价格精度。未知 ID 保守保留查询。
- 多标的规则已达到当日整体预算或本规则当日限额时，跳过查询。美股仍按市场交易日期区分单标的规则计数。
- 港元等文本播报须有异动模板余额。CNY/USD 播报的模板还取决于实际价格位数，查询前保守检查两组可能的余额，查询后按实际模板再次过滤，避免过滤掉高精度播报。
- 保留已发送目标规则的自动关闭补偿。扫描无新任务不阻止已有任务分发，扫描异常时也继续走原有分发链路。
- 同标的跨用户去重、每批最多 30 个标的的机制保持不变。扫描返回 `scanStats`（considered、eligible、quotedAssets、marketCalls），便于比对过滤效果，不包含用户身份。

## 规模模拟与预算

已用模拟数据库验证：100 人每人 5 个不同 A 股、均有授权且交易中，需要 17 次行情云函数调用/轮；同一场景夜间为 0 次。100 人都关注相同 5 个标的时，为 1 次/轮。

以每月 30 天、22 个 A 股交易日、每交易日 240 分钟估算：

| 项目 | 估算调用 |
| --- | ---: |
| 固定分钟定时器 | 43,200 |
| 500 个不同 A 股的交易时段行情，17 批/分钟 | 89,760 |
| 上述两项合计 | 132,960 |
| 相对 200,000 次剩余 | 67,040 |

这些不是总用量保证。收盘/自定义播报窗口、港美股与黄金、前台行情刷新、搜索/图表/账户等操作、重试或重复云端触发器均会额外占用。授权耗尽、规则关闭或每日额度耗尽会使后台实际用量更低。数据库读取与计算资源也有独立消耗，本次并不消除每轮扫描的数据库访问。

## 验证与部署

运行 `node --test --test-timeout=30000 tests/*.test.js`，包含零授权恢复、分组模板、证券时段、港美股夏令时、跨午夜、日限额、500 标的分批及已有任务分发回归。测试不调用真实云端、不消耗通知授权。

上线只需重新上传并部署整个 **sendTask** 目录（含 `asset-tasks.js`、`rules.js`、市场日历文件），选择云端安装依赖；本次没有修改 `marketData`。保持既有一分钟 `dispatchTimer`，检查云端没有额外旧 `scanTimer`。现有建议的 60 秒运行超时继续适用，实际云端耗时需部署后核验。无需新增集合或清空数据库。

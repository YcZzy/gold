# 持仓读取超时修复（2026-11-02）

用户提供真实错误：ledger -504003，Invoking task timed out after 3 seconds。CLI起初核对ledger和callBudget均Active、3秒；ledger估值原先嵌套marketData，最多等5秒，加上账本读取/冷启动可能被平台提前中止。

修复：

- ledger所有估值响应改为服务器quoteCache批量查询：最多30个实际非零持仓一次where+in查询，不再逐标的doc.get，不再调用外部行情。缓存读取最多等待1.5秒，失败仍返回账本并明确估值缺失。身份、7天保留期、未来时间过滤和旧报价stale标识保留；不伪造实时价格。
- 页面打开只读取ledger；手动刷新/下拉先显示账本，再独立market.quotes，完成后重读服务器权威估值；行情失败不把已加载账本设为离线，不自动提交交易。隐藏页面后不更新旧请求。
- 对ledger只读、备注和撤销只预扣1单位；单条交易最多2、导入/预览最多31。额度服务短暂失败的冷却只影响新领取，已有额度仍可正常使用。

验证：Node全量584/584通过，新增无外部行情依赖、单次批量缓存读取、独立刷新失败保留页面、单信用读取及额度服务冷却回归；JS语法、持仓WXML编译、git diff --check通过。独立复查未发现重要问题。

已通过微信开发者工具CLI将完整ledger部署到utils/app-config.js既有云环境，上传及云端依赖安装成功。部署后CLI确认ledger Active、当前超时10秒（读取到的云端配置，不声称由本轮修改）。模拟器实际打开持仓页成功显示，缓存估值标记正确；一次新ledger网络请求总耗时3.94秒，包含客户端/传输/冷启动，不能作为云端纯执行耗时或长期性能保证。

前端utils/cloud-call-budget.js与pages/holdings更新仍需上传体验版/正式发布，才能让手机使用独立行情刷新与新的预扣成本；本次没有上传发布前端。没有创建测试流水或修改用户持仓数据。

边界：新增交易、导入/预览在证券资料缺失或过期时仍需服务器身份核验，可能比普通读取慢；未绕过这类写入校验。10秒并不保证大批导入都完成。新增额度函数的通用错误仍需结合其自身云日志定位，不能仅凭本次ledger超时日志断言callBudget也曾超时。

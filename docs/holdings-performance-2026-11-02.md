# 持仓性能与交互优化（2026-11-02）

## 已实现

- 当前持仓页面实例内，成功快照15秒内返回复用；显示偏好改变、读取失败、超时或手动刷新重新读取。不写入设备存储。
- 同一 ledger client 中重叠的 list 合并为一次调用，返回各自副本；写操作开始和结束均隔离旧读取。失败可以重新读取，写操作保留原有幂等请求标识和版本冲突。
- 选择账本已有标的无需客户端 resolve；服务端仍读取受权限保护的 instruments 并校验身份、类型、币种和精度。资料24小时内有效，未来时间、过期或异常回源；黄金资料固定在服务端。
- 只请求非零持仓报价，空账本、纯现金和全清仓不调用行情云函数。已清仓记录仍保留数量、成本与已实现盈亏；未获取报价时不提供该标的现价与交易日估算。
- saveNote 只读 quoteCache，不嵌套调用 marketData。缓存超过15秒标记 stale；超过7天、未来时间、身份错误或缺失不可用于估值，明确显示报价缺失。下拉/按钮刷新正常请求报价。
- 行情和缓存读取等待上限5秒，超时返回账本及估值缺失提示。此上限仅约束估值等待，不保证整次云函数5秒完成，也不会取消已经发出的 marketData 调用。
- 首页增加交易记录、资产明细和刷新入口，刷新保留内容；无匹配结果可一键清除搜索、排序及清仓筛选。历史标的查找改为索引。

## 限定场景调用预算

以下包含顶层与嵌套云函数，不包含数据库操作及行情供应商HTTP：

| 场景 | 原逻辑 | 新逻辑 |
| --- | --- | --- |
| 15秒内返回已加载页面 | ledger + marketData | 0（偏好未变且未失败） |
| 保存备注，有在持标的 | ledger + marketData | ledger |
| 全清仓读取 | ledger + marketData | ledger |
| 已有标的选择 | marketData resolve | 0 |
| 有效目录资料下保存证券流水 | ledger + resolve + quotes | ledger + quotes |

资料失效时仍需 resolve；混合持仓仍有一次批量 quotes，但其资产数减少。以上是代码路径预算，不是生产总调用量或延迟实测。

# 自选行情与提醒

微信小程序：黄金、沪深 A 股及 ETF / LOF、北交所股票、港股及 ETF、美股及 ETF 的自选列表、中文/英文/代码/拼音首字母搜索、独立行情详情和按标的提醒。保留纸感与黑金主题、现有图表和微信订阅授权账本。

主题以本设备已保存的选择为准，所有页面显示时重新应用同一主题，导航栏和底部导航图标同步更新。只有本设备没有有效主题记录时，才从云端偏好初始化；旧请求、离线状态缓存及云端保存失败均不会回滚本地选择。主题切换即时生效，云端保存串行执行；保存失败时保留本地选择，下次主动切换再次保存。

原生顶部导航在页面加载、显示和主题切换时通过 `wx.setNavigationBarColor` 显式同步背景色与文字色；窗口背景和页面内容背景由各页的 `page-meta` 绑定同一个主题，页面尺寸变化期间的底色通过 `root-background-color` 设置。全局 `backgroundColorContent` 为尚未渲染 WXML 的页面容器提供纸感底色，避免使用默认白色；它与下拉区域的 `backgroundColor` 分别配置。导航颜色只由 API 更新，避免与 WXML 声明竞争；自定义底栏尚未挂载时由其挂载生命周期同步主题。

底部导航使用原生自定义悬浮玻璃栏，支持纸感 / 黑金材质、按压反馈和选中胶囊滑动回弹。导航选中态以实际页面路由为准，切换失败可重试；三个 Tab 页预留浮栏高度和底部安全区。首页添加、我的主题按钮共用玻璃材质。`backdrop-filter` 仅作背景模糊增强，不支持时仍保留高不透明度着色底、边缘高光与阴影；减少动态效果偏好下关闭动画。当前效果不包含实时背景折射，不更改行情 Canvas。

## 页面

- **自选**：列表显示名称、代码、价格、涨跌幅、涨跌额、来源报价时间和已开启提醒数；备注及标签同步展示。支持添加、管理模式下手势拖拽排序、右侧删除。返回详情保留原列表位置。
- **搜索**：中文片段、代码、拼音首字母联想；结果主体预览详情，右侧原地加入自选。完整拼音匹配不作首版保证。
- **详情**：固定标的身份、价格与真实行情时间、分时/K 线、基本行情数据、黄金国际参考、本标的提醒入口；新增图表目标提醒、自定义均线、MACD 和关注笔记。
- **提醒**：跨标的汇总、微信授权次数、最近发送状态；每只标的独立编辑价格/波动/定时/收盘规则。
- **我的**：主题、通用免打扰、授权、数量权益。首版免费 5 个自选、30 条启用规则；服务端 VIP 权益预留 30 个自选，没有购买流程。

## 完整看盘工作区

自选首页与「我的」均可进入「行情发现」「我的持仓」「分组与备份」，沿用原有三个底部 Tab。

- **自选组织**：最多 10 个分组、16 字组名，每组独立手动/价格/涨跌幅/成交额排序；按市场、标的类型、价格、涨跌幅及备注关键词筛选。条件选股仅针对已取得的自选行情。管理模式显示完整主列表并保留拖拽；删除分组不会删除股票或提醒。
- **显示与备份**：灰阶、紧凑列表、隐藏持仓金额，以及涨跌额/时间/备注显隐。代码文本、JSON 和 CSV 先识别预览；同代码多市场须明确选择，确认后服务端原子校验额度。JSON 保留笔记、标签、空分组、组内手动顺序及排序；CSV 用于列表交换。合并导入保留已有备注和同名分组设置，不恢复授权或提醒，不绕过原自选名额。
- **图表**：历史范围与日/周/月粒度分别选择。周/月由交易所本地日期日线聚合；区间起点可能截断、当前周期未完结分别提示。增加 BOLL(20,2)、成交量 MA5/MA10，未知量不补零。缩放、左右浏览、回最新及“查看/平移”手势使用完整已加载历史计算指标再切视窗，避免缩放改变种子；更换历史范围仍可能改变起始段数值。
- **行情发现**：8 种白名单指数本机自定义关注；新浪行业/概念、成分股、沪深北涨跌幅和成交额榜；东方财富估算资金榜。新浪列表无源日期时仅显示获取时间，资金列表显示来源日期和获取时间。可进入详情或原地加入自选，不将指数/板块伪装成交易证券。
- **五档与资金**：沪深普通股票详情按需展开腾讯五档（单位股），以及东方财富主力/超大单/大单/中单/小单净额与占比。挂单快照不是逐笔成交；资金分类是供应商估算，不等于机构真实身份或北向资金。
- **手工持仓**：独立台账支持期初、买卖、费用、现金入出金、分红/独立费用、拆合股、历史修订/撤销、备注和 JSON 预览恢复。CNY/HKD/USD 分账，支持市值、盈亏及收益率排序。持仓与自选独立，删除自选不等于清仓。

台账采用移动加权平均成本，买入费用计成本、卖出费用扣收入；当日盈亏按行情所属交易日和当地日期流水估算。无有效报价、昨收或交易日证据时不伪造完整估值/日收益；黄金、拆合股等缺少可靠基线时显示不可计算。累计收益率不是年化或券商税务结果。上限为 30 个台账标的、1000 条含修订流水、1000 次写操作和 512KB 文档；隐藏金额不会自动擦除用户主动生成的原始备份。

发现能力分模块缓存，来源故障最多展示 24 小时旧快照并标识。2026-10-29 首次真实验收 11/11 成功，最终复测为 9/11：资金榜和单股资金的东财源连接中断，其余成功，未验证到独立资金备用。因此资金功能已实现，但不能承诺该公开源持续可用。见[调研](docs/research-market-discovery-2026-10-29.md)和[最新复测](docs/discovery-smoke-2026-10-29.json)。

完整范围、未纳入功能及部署验收见[版本交付记录](docs/complete-workspace-delivery-2026-10-29.md)。

## 数据与兜底

### 场内基金、笔记与指标

- LOF 目前接受上交所 `501xxx` / `502xxx`、深交所 `16xxxx` 的候选代码，但代码前缀本身不证明基金类型。搜索和接入均要求腾讯精确证券代码、LOF 类型及人民币报价证据，未知类型不接入；ETF 不会被误分类为 LOF。场内基金最低保留三位小数，未接入场外基金净值。真实只读验证见 [lof-validation-2026-10-29.md](docs/lof-validation-2026-10-29.md)。
- 已自选标的的详情底部「关注笔记」可编辑 120 字备注、最多 3 个各 8 字标签。点击保存后由 `portfolio` 事务保存；输入中不会自动提交。清空内容再保存可删除笔记；移除自选也会清理笔记。编辑冲突保留草稿，可明确选择「载入最新备注（替换草稿）」。笔记属于用户数据，不写入公共证券目录。
- 「目标提醒」复用本标的已开启的涨到价 / 跌到价规则；图表范围内显示虚线，范围外保留文字摘要，不拉伸价格轴。距离采用 `(目标价－当前显示价) / 当前显示价`，同时展示带符号差额；当前显示价为缓存时距离也仅供参考。新增或编辑规则仍从「设置提醒」进入，不自动创建买卖指令。
- 详情「指标设置」支持 1–3 条、1–250 日且不重复的价格均线，可整体关闭，默认 MA5 / MA10。K 线副图可在成交量与 MACD(12,26,9) 间切换；设置只保存在当前设备，不改变行情刷新频率。分时仍显示原有价格、均价、昨收及适用的成交量。
- 指标仅用当前已加载的 K 线计算。MACD 的 EMA 从首个收盘价初始化，柱值为 `2 × (DIF－DEA)`；不足 26 根提示样本较少，切换历史区间可能改变起始段数值。长周期均线不足完整样本时不画线，不补造历史数据。

本轮上线需先更新部署 **marketData**（含 LOF 元数据与依赖文件）及 **portfolio**（含 `securities.js`），再更新前端。沿用现有集合与权限，无新增集合，无需清空数据。`sendTask` 的原有非黄金证券路径可复用，不因本轮新增备注或图表指标改变提醒策略。本地代码和模拟测试通过不代表云端已部署。

证券搜索合并已验证的数据源及官方证券目录。股票和 ETF 报价使用腾讯及按市场验证的备用源，美股增加 Yahoo 常规交易价格备用，校验精确代码、交易所、类型、币种和原始行情时间。分时与日 K 优先使用腾讯不复权数据，北交所日 K 使用当前代码的东财和新浪路由。腾讯的代理、直连地址只是同源线路备用。黄金保留东财、新浪及上金所路径。所有历史图表使用不复权口径；Yahoo／Nasdaq 历史数据已实测存在复权差异，未作为通用不复权图表备用。美股独立不复权备用仅在对应东财映射及历史均校验通过后启用；其余情况下依赖腾讯同源线路，不将未核验来源标为可用。空值、错误资产、时间缺失和异常 OHLC 不会被当作有效数据。

港股各币种柜台分别保存，单位使用港元、人民币或美元；美股完整供应商代码与用户代码分别保存，例如 `usBRK.B` 的腾讯图表身份为 `usBRK.B.N`。ETF 及低价证券保留经过验证的报价精度。未确认的成交量单位不显示为股或手。行情时间以北京时间显示，美股图表按纽约交易日和当地时间显示；休市、午休、延迟和缓存读取失败分别标注。

行情时间和获取时间分开保存。缓存和延迟数据明确标注；新价格预警只使用有效的新鲜报价。短时规则比较同标的、同源、约 15 分钟前的有效基准；恢复行情或切换数据源后可能需要重新积累基准。

云函数未部署或连接失败时，前端允许只读展示已有自选缓存及旧黄金行情链路。黄金本地回退会显示延迟和时间待确认；修改自选或规则必须服务端成功，股票数据失败不会伪造价格。

本地黄金报价优先读取东财分时末点，分时失败才尝试报价端点，沪金最后尝试日 K 收盘价。`push2` / `push2delay` 已复现空响应，`push2his` 也存在间歇失败；该本地链路无法保证东财整体故障时可用。若堆栈出现 `withGoldFallback → localQuote → gold-api`，说明行情云函数连接失败，应确认 `marketData` 已上传部署到 `utils/app-config.js` 指定环境，查看云函数调用错误和云端日志。独立的新浪/上金所备用源由云函数提供。

公开接口的覆盖和可用性需按市场验证。现有接口没有在本项目中确认长期 SLA、调用配额或会员产品的数据使用授权。

## 云端部署

本地开发完成不表示云端已更新。发布前按以下顺序操作：

1. 在微信开发者工具确认 `utils/app-config.js` 中的环境和两个现有订阅模板 ID。
2. 上传并部署 **initDb**，选择「云端安装依赖」，云端执行一次 `{}`。它只幂等增加所需集合（含本版新增 `investmentLedgers`），保留所有旧数据。
3. **设置数据库权限**：云开发控制台中，将本项目全部 13 个集合设为「所有用户不可读写」，仅由云函数访问。每个集合的自定义规则为 `{ "read": false, "write": false }`；完整清单见 [database-permissions.json](docs/database-permissions.json)。此清单是人工配置参考，不会随函数上传自动生效。尤其 `entitlements`、`portfolios`、`subscriptions` 不能允许客户端自行创建或修改，否则会绕过会员、自选或次数校验。
4. 上传并部署 **marketData**、**portfolio**、**ledger**、**sendTask**、**getStatus**、**savePrefs** 和 **registerAuth**，选择云端安装依赖。`ledger` 需上传整个目录（含 `engine.js`、`securities.js`）；`portfolio` 需包含 `workspace.js`，`marketData` 需包含 `discovery.js`。`marketData` 依赖 `iconv-lite`；`sendTask` 包含 `rules.js` 与 `asset-tasks.js`。建议采用支持现代 JS 的 Node.js 运行环境。
5. `sendTask` 与 `ledger` 建议配置 60 秒超时；`marketData` 与 `portfolio` 建议至少 30 秒。`marketData` 需一并上传目录、市场时间和日历文件；`sendTask` 需一并上传日历文件。先等待部署完成，再右键 **sendTask → 上传触发器**，确认仅保留 `dispatchTimer` 每分钟（`0 * * * * * *`）；若控制台仍有旧 `scanTimer`，手动删除。每轮先扫描行情再立即分发，不再依赖两个定时器的先后顺序。函数仍处于 Updating 时不要重复上传触发器。
6. 查询如提示缺少索引，按控制台提示建立 `sendTasks` 的 `(status, triggerTime)`、`(openid, status, sentAt)` 等索引。缓存过期清理需要按控制台提示建立对应过期时间索引。
7. 上述函数和权限均准备完成后再编译/预览新前端。第一次成功获取自选时，portfolio 将旧黄金偏好迁移为内嵌规则，并原子写入迁移标记。旧已发送或结果不明的到价任务不会自动重新开启。

前端主要通过云函数访问新股票接口。黄金兼容回退和国际参考仍使用 `utils/gold-api.js` 的原有 request 域名配置；生产版需保持这些已配置域名。

会员权益仅从服务端 `entitlements/{OPENID}` 读取：有效的 `{tier: "vip", expiresAt: <毫秒时间戳>}` 扩展自选到 30 个。此集合必须禁止所有客户端访问，仅后台管理或未来已验证的支付回调能写入。

## 提醒规则

沿用原有两个模板：普通定时/收盘用简报模板；港元及超过金额字段数字长度限制的简报改用异动模板的文本价格字段，完整保留币种和精度，并扣除实际使用模板的授权次数。涨到价、跌到价、日内波动、短时急变继续用异动模板。点击消息进入对应标的详情。

- 每个用户每日常规最多 6 条、到价最多 4 条，两个预算独立；每标的每类每天最多 1 条。
- 到价类成功后关闭对应规则版本；修改条件或重新开启会生成新版本。删除自选同时删除该标的全部提醒规则；已排队的旧提醒在发送前校验失效并取消，重新添加不会恢复提醒。
- 价格与波动提醒仅在标的常规交易时段使用新鲜报价；短时基准不能跨交易日、午休或数据源。日内波动按各市场交易日去重，美股自动处理纽约夏令时。
- 证券收盘简报在对应收盘边界后 10 分钟起监测；港股等待收市竞价最晚边界，半日市和美股提前收盘按官方日历处理。沪金保留 15:40 策略；伦敦金使用定时播报。
- 定时播报按北京时间，「仅周一至周五」仅代表星期。已核验的证券日历覆盖：沪深／北交所 2026、香港 2026–2027、美国 2026–2028；未知年份不启用收盘简报。
- 约每 1 分钟检查行情，达标任务立即到期并在同次调用内分发，取消原有 15 秒等待。正常负载下检测等待约 0–60 秒，另加行情请求、云端调度和微信送达耗时；仍可能错过分钟间隔内的短暂触价，不能保证秒级送达。短时历史按分钟采样，仅保留最近 30 分钟、最多 32 个快照。免打扰只在任务有效期内顺延。
- 已确认临时失败退还授权和每日预算后重试；结果不明保留占用并标记待核查，不盲目重发。预算预占、自选更改和规则消费均使用事务。

### `portfolio` 调用报 3 秒超时

若报 `-504003` / `FUNCTIONS_TIME_LIMIT_EXCEEDED` 且包含 `timed out after 3 seconds`，在云开发控制台选择对应环境，进入 **云函数 → portfolio → 配置 / 高级设置 → 超时时间**，改为 **30 秒**并保存。该函数返回自选时还会解析证券元数据；默认 3 秒可能不足。`marketData` 同样按上方部署要求配置至少 30 秒。运行上限是云端配置，重新编译小程序不会修改它；若调整后仍超时，应查看函数日志定位数据库或元数据解析耗时。

持仓录入的候选标的只读已有持仓快照与自选缓存，不在打开表单时远程拉取 `portfolio`；无缓存仍可搜索，选择标的仍需服务端核验。此优化不替代其他自选功能所需的云端超时配置。

### `ledger` 返回 `ledger-unavailable`

这表示调用进入了函数，但遇到未作为业务错误处理的异常；仅凭通用提示无法确认原因。`ledger` 会在云端记录 `ledger operation failed`，包含 action、stage、错误码与错误消息，不记录请求中的完整流水。按响应的 requestID 查找同次调用日志，区分 `resolve-assets`（标的核验）、`read-ledger`、`replay-ledger`、`write-ledger`、`valuation`。

首次建账兼容 SDK 的 message / errMsg 两种错误格式。文档不存在视为空账本；集合不存在会明确返回 `ledger-not-initialized`，此时更新部署并运行 `initDb`，保留所有旧数据。更新后需重新部署整个 `ledger` 目录并安装云端依赖；运行超时按部署清单设为60秒。修改本地文件或前端重新编译不会更新云函数。

若无法查询云端日志，更新后的 `ledger` 在未预期异常响应中附带 `diagnostic: {stage, code, version: 1}`，可直接从开发工具 Network 的 Response 复制该对象定位；其中不包含原始异常消息、身份或流水内容。旧版响应不带此字段，需要先重新部署云函数。

# 自选行情与提醒

微信小程序：黄金与沪深 A 股自选列表、中文/代码/拼音首字母搜索、独立行情详情、按标的设置提醒。保留纸感与黑金主题、现有图表和微信订阅授权账本。

## 页面

- **自选**：列表显示名称、代码、价格、涨跌幅和已开启提醒数；支持添加、管理模式下手势拖拽排序、右侧删除。返回详情保留原列表位置。
- **搜索**：中文片段、代码、拼音首字母联想；结果主体预览详情，右侧原地加入自选。完整拼音匹配不作首版保证。
- **详情**：固定标的身份、价格与真实行情时间、分时/K 线、基本行情数据、黄金国际参考、本标的提醒入口。
- **提醒**：跨标的汇总、微信授权次数、最近发送状态；每只标的独立编辑价格/波动/定时/收盘规则。
- **我的**：主题、通用免打扰、授权、数量权益。首版免费 5 个自选、30 条启用规则；服务端 VIP 权益预留 30 个自选，没有购买流程。

## 数据与兜底

搜索按东方财富 → 腾讯智能联想 → 本地已缓存目录/搜索结果降级。股票报价按腾讯 → 东财 → 新浪降级；股票分时/K 线以东财为主、腾讯为备。黄金报价保留东财并增加新浪独立来源，沪金图表增加上金所来源，伦敦金图表增加新浪来源。所有历史图表使用不复权口径。超时、空值、错误资产、无效时间都会参与校验。

行情时间和获取时间分开保存。缓存和延迟数据明确标注；新价格预警只使用有效的新鲜报价。短时规则比较同标的、同源、约 15 分钟前的有效基准；恢复行情或切换数据源后可能需要重新积累基准。

云函数未部署或连接失败时，前端允许只读展示已有自选缓存及旧黄金行情链路。黄金本地回退会显示延迟和时间待确认；修改自选或规则必须服务端成功，股票数据失败不会伪造价格。

本地黄金报价优先读取东财分时末点，分时失败才尝试报价端点，沪金最后尝试日 K 收盘价。`push2` / `push2delay` 已复现空响应，`push2his` 也存在间歇失败；该本地链路无法保证东财整体故障时可用。若堆栈出现 `withGoldFallback → localQuote → gold-api`，说明行情云函数连接失败，应确认 `marketData` 已上传部署到 `utils/app-config.js` 指定环境，查看云函数调用错误和云端日志。独立的新浪/上金所备用源由云函数提供。

公开接口的覆盖和可用性需按市场验证。现有接口没有在本项目中确认长期 SLA、调用配额或会员产品的数据使用授权。

## 云端部署

本地开发完成不表示云端已更新。发布前按以下顺序操作：

1. 在微信开发者工具确认 `utils/app-config.js` 中的环境和两个现有订阅模板 ID。
2. 上传并部署 **initDb**，选择「云端安装依赖」，云端执行一次 `{}`。它只幂等增加所需集合，保留所有旧数据。
3. **设置数据库权限**：云开发控制台中，将本项目全部 12 个集合设为「所有用户不可读写」，仅由云函数访问。每个集合的自定义规则为 `{ "read": false, "write": false }`；完整清单见 [database-permissions.json](docs/database-permissions.json)。此清单是人工配置参考，不会随函数上传自动生效。尤其 `entitlements`、`portfolios`、`subscriptions` 不能允许客户端自行创建或修改，否则会绕过会员、自选或次数校验。
4. 上传并部署 **marketData**、**portfolio**、**sendTask**、**getStatus**、**savePrefs** 和 **registerAuth**，选择云端安装依赖。`marketData` 依赖 `iconv-lite`；`sendTask` 包含 `rules.js` 与 `asset-tasks.js`。建议采用支持现代 JS 的 Node.js 运行环境。
5. `sendTask` 建议配置 60 秒超时；`marketData` 与 `portfolio` 建议至少 20 秒。先等待部署完成，再右键 **sendTask → 上传触发器**，确认仅保留 `dispatchTimer` 每分钟（`0 * * * * * *`）；若控制台仍有旧 `scanTimer`，手动删除。每轮先扫描行情再立即分发，不再依赖两个定时器的先后顺序。函数仍处于 Updating 时不要重复上传触发器。
6. 查询如提示缺少索引，按控制台提示建立 `sendTasks` 的 `(status, triggerTime)`、`(openid, status, sentAt)` 等索引。缓存过期清理需要按控制台提示建立对应过期时间索引。
7. 上述函数和权限均准备完成后再编译/预览新前端。第一次成功获取自选时，portfolio 将旧黄金偏好迁移为内嵌规则，并原子写入迁移标记。旧已发送或结果不明的到价任务不会自动重新开启。

前端主要通过云函数访问新股票接口。黄金兼容回退和国际参考仍使用 `utils/gold-api.js` 的原有 request 域名配置；生产版需保持这些已配置域名。

会员权益仅从服务端 `entitlements/{OPENID}` 读取：有效的 `{tier: "vip", expiresAt: <毫秒时间戳>}` 扩展自选到 30 个。此集合必须禁止所有客户端访问，仅后台管理或未来已验证的支付回调能写入。

## 提醒规则

沿用原有两个模板：定时/收盘用简报模板；涨到价、跌到价、日内波动、短时急变用异动模板。各标的共享对应授权次数。价格与消息使用正确名称、币种、单位；点击消息直接进入该标的详情。

- 每个用户每日常规最多 6 条、到价最多 4 条，两个预算独立；每标的每类每天最多 1 条。
- 到价类成功后关闭对应规则版本；修改条件或重新开启会生成新版本。删除自选同时删除该标的全部提醒规则；已排队的旧提醒在发送前校验失效并取消，重新添加不会恢复提醒。
- 沪深收盘简报在 15:10 后，仅使用当日不早于 15:00 的有效报价；沪金保留 15:40 策略。伦敦金提供定时播报，不假定伦敦收盘时刻。
- 定时「仅周一至周五」按星期判断，未接入完整交易日历；收盘简报通过当日报价日期避免休市日重复播报。
- 约每 1 分钟检查行情，达标任务立即到期并在同次调用内分发，取消原有 15 秒等待。正常负载下检测等待约 0–60 秒，另加行情请求、云端调度和微信送达耗时；仍可能错过分钟间隔内的短暂触价，不能保证秒级送达。短时历史按分钟采样，仅保留最近 30 分钟、最多 32 个快照。免打扰只在任务有效期内顺延。
- 已确认临时失败退还授权和每日预算后重试；结果不明保留占用并标记待核查，不盲目重发。预算预占、自选更改和规则消费均使用事务。

## 验证

运行 `node --test tests/*.test.js`。测试替代微信 SDK、云数据库和消息发送，不消耗真实授权。覆盖接口解析/降级、搜索、列表和详情导航、按标的规则、旧数据迁移、并发名额、事务重试、失败退款、未知发送结果及旧黄金回归。

实际云函数部署和真机订阅消息接收需要按上面的顺序完成后验证。请勿把本地模拟发送成功当作真实消息送达。
